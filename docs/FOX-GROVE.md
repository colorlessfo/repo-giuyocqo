# 小狐狸的专注树屋

## 使用

电脑左侧与待办区之间的分隔线已替换为长树藤，小狐狸原来的位置变为树根小窝。小窝上方的“开始专注”打开树屋；点击狐狸会回应并跳跃。手机在页面上方提供“小狐狸的专注树屋”入口。窄屏专注时，场景和倒计时并排显示。

选择 15、25、45、60 分钟，或输入 1–180 分钟。可选填本次专注内容，现有未完成待办可以作为输入建议，但专注不会修改其截止时间或完成状态。开始后可收起窗口继续使用网站，左侧或手机入口显示剩余时间。刷新、切换页面或设备都可以继续；暂停不计时，提前结束需确认且不扣已经取得的奖励。

狐狸会沿藤蔓攀爬、在枝头停留、寻找微光，暂停时休息。探索动画中的发现是氛围表现，只有完整倒计时结束后点击“领取本次战利品”，才将奖励放入账号背包。每分钟 2 橡果；材料按苔光种子、暖光树脂、月光石循环带回，至少 1 份，50 分钟可取得 2 份，75 分钟 3 份。

“奇遇商店”提供霜雪、暮紫、蜜糖三款狐狸皮肤，林间树屋和观星小屋，以及暖灯、白花和星星装饰。显示固定价格与所需材料，没有付费、抽奖或现实货币。兑换后立即使用；装饰可收起，皮肤和房屋可切回默认。该装扮作用于树屋伙伴，任务原有的小伙伴选择继续保留。

“背包与记录”显示材料、累计时间和最近 40 段已领取的专注，并可导出记录。正式账号进度保存在服务端；体验模式只保存在这个浏览器，不与正式账号混合。

## 保存与计时

- 私有 `groves` 表按 `user_id` 保存当前倒计时、奖励、装扮和最近记录。随应用启动自动建表，不变更原 `entities` 数据，不需要新服务、付费资源或密钥。
- `/api/grove` 和 `/api/grove/action` 复用现有 HttpOnly 会话、来源校验和服务端限流。所有读写只使用当前登录用户，客户端不能指定其他账号。
- 开始、暂停、继续和领取均使用服务端时间。奖励、价格和材料在服务端计算，浏览器修改倒计时或余额不会得到相应奖励。
- 同一账号只保留一个当前专注。所有修改在数据库用户锁内执行，检查版本；同时操作时刷新进度并提示，不静默覆盖。
- 操作在请求前保存到账号隔离的本机缓存。响应丢失、刷新或重连后使用同一操作编号重试；事务中的收据防止重复奖励、重复扣款和重复启动。收据复用原 `mutations` 表的 `grove:` 命名空间。
- 约六秒同步，并在窗口恢复可见、重新联网或获取焦点时刷新。客户端使用服务端时间校准显示，游戏收益以服务器判断为准。
- 离线时已有倒计时继续显示；新操作等待联网确认。余额和装扮得到服务端确认后才更新。

## 发布与备份

沿用原 Render 服务、`qiyu-ddl` 分支与 PostgreSQL 配置即可。首次启动自动建立私有表，PostgreSQL 的匿名和 authenticated Data API 角色不能访问这些表。原任务、笔记、课程及设置均不变。

“备份与日历导出”的既有 JSON 文件不包含树屋，可在树屋单独导出记录；该导出供查看，不能导入修改奖励。完整恢复树屋需数据库备份，保留 `groves`、`mutations` 和用户表。回退旧版本不会删除树屋表，之后升级可继续使用。

## 验证与边界

服务端测试覆盖拒绝提前领取、忽略客户端伪造时间、暂停时间不计入、两设备抢领只发一次、重试、余额和材料不足、并发兑换、未购买装扮不能使用、账户隔离、实例重启持久化，以及不改变任务数据。分别在 SQLite 与 PostgreSQL 18 运行。

浏览器流程覆盖暂停、刷新、恢复、抚摸、领取、兑换皮肤与灯饰、兑换已生效但响应中断后的重试、第二设备装扮一致和另一账号隔离。测试账号通过私有数据库准备倒计时的最后几秒；应用没有测试加速入口，领取和兑换仍走实际服务端接口。

这是陪伴式专注计时，不能证明人在屏幕前持续专注。切到后台或关闭网页后时间会继续，领取时由服务端核对；没有关闭网页后的系统推送。动画尊重全局效果开关与系统减少动态效果设置。真机 Safari、设备休眠和不同网络仍需实际体验。
